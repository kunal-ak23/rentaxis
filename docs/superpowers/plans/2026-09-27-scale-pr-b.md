# Scale PR B — paged pages and async pickers — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** No daily web page loads the whole units or renters table; every unit/renter picker searches the server; the remaining unbounded pages (renters, gate-pass report) page on the server; list filters survive a reload/share via the URL.

**Architecture:** One server-backed picker (`AsyncSearchSelect`, the `SearchableSelect` UI with the filtering moved to the server) plus two thin wrappers (`UnitPicker`, `RenterPicker`) over the Scale PR A endpoints `/units/search`, `/renters/search`; row labels come from a batched, id-keyed names cache over `/units/names`, `/renters/names`. `useNameLookup` is narrowed to `"properties"` (≈60 rows, fine) so `tsc` proves no whole-table unit/renter read is left. Two backend additions: `status`/`propertyType` on unit search, a renter-scoped cheque read, and a paged gate-pass report.

**Tech Stack:** Next.js 16 + TypeScript strict + next-intl (EN/AR, RTL) + Tailwind; vitest + Testing Library; Spring Boot 4 / Java 21 / Postgres, JUnit ITs on `AbstractPostgresIT`.

**Spec:** `docs/superpowers/specs/2026-09-25-scale-track-design.md` (items #4, #5, #6 FE, #8, #14, #15, #22). Audit 2026-09-27: #10 penalty queue and #23 parallel bulk post are **already done** (`PenaltyQueue.tsx:63`, `lib/leases/bulkPost.ts:4`) — no work.

- OSIV is OFF in prod: map DTOs inside `@Transactional` service methods.
- Liquibase is append-only; next changeset number is **155** (only if an index is needed).

- Frontend calls go through `/api/proxy/v1/...`; never a hardcoded backend URL.
- Old unbounded endpoints stay (mobile and back-compat) — the web just stops calling them.
- Commits: `git commit -- <paths>` only; trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus
1. **A selected value outside the current search results** (edit a draft lease whose unit is now OCCUPIED; a filter restored from the URL) must still show its label, not a blank or raw UUID → Task 2 test "shows the selected label via names".
2. **Out-of-order search responses** (type "07", then "070" — the slower "07" reply lands last) must not replace the newer results → Task 2 test "drops stale responses".
3. **Arabic locale**: renter options/labels show `nameAr` when present, unit labels unchanged; search matches Arabic names (server does) → Task 2 test "AR label".
4. **A search that fails** (403 for a role, 5xx) shows an inline error row and keeps the current value; never clears the form field → Task 2 test "error keeps value".
5. **More than 200 ids to label** (a general-ledger page with 500 rows) is chunked into ≤200-id `/names` calls, and repeated ids are fetched once → Task 3 test "chunks and dedupes".
