Use an authorised tenant administrator to inspect online rent collection. This walkthrough stays in the provider test environment and does not launch a real payment.

On Payment Gateway Configuration, Razorpay is selected and the organisation shows a current Test Mode configuration. Test Mode is the safe place to verify readiness before any live charge is possible. Check the provider name, the current status, and the switch that keeps the sandbox active. Production mode should only be enabled after approved credentials, callback settings, provider testing, and operational sign-off are complete.

The credential fields are intentionally empty in the form. The helper text confirms that the existing API key, API secret, and webhook secret are retained, while the stored API key is shown only as a masked value. RentAxis never puts the original secrets back into the page. Use provider-issued test values when a rotation is actually required, and never paste a live secret into a recording, ticket, chat, or source file. The Test Connection action can check readiness without displaying credentials. Save only an intentional change, then wait for the confirmation banner. A masked retained value is not proof that the provider accepts it, so treat the connection result as the source of truth.

Next, Rent Collection Settings applies the payment policy to a specific property. The prepared property shows a due day of one, a five-day grace period, no late-penalty type, and online payments disabled. The property-level switch controls whether eligible installments may advertise online collection. Cheque-failure fine overrides remain visible for review. Enable this switch only after the gateway and property policy have been approved, then verify the renter-facing payment view in a separate test. Stop before launching a real provider checkout. If a gateway or credential is uncertain, deactivate it first and investigate rather than asking renters to retry repeatedly.
