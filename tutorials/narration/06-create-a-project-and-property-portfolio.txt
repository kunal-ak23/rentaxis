This tutorial shows how the property portfolio is created and reviewed before units, leases, tickets, listings, finance, and resident services depend on it. We are using the prepared RentAxis Tutorial Studio tenant, so no additional production record is saved during this recording.

Open Properties and select Add Project. The form captures the English and Arabic names, emirate, type, address, Makani number, and fixed expenses for a project or portfolio group. Search before creating so you do not duplicate an existing record. Use approved bilingual and synthetic location data only. Review every field from top to bottom before creating once in a real onboarding; address and expense values feed later operational and financial views.

Open the prepared RentAxis Academy Residence Tower and compare its identity, residential type, address, manager assignment, and maintenance contact. A property is the physical operating boundary for buildings, units, leases, amenities, parking, and assigned staff. Keep its address and identity consistent with the approved source data, and verify manager assignment separately from tenant administration.

Use Card view for visual scanning of property names, occupancy, and summary information. Switch to Table view for compact comparison across a larger portfolio, then use search and the Manage action to open the same record. These views are two ways to reach the same property data, not separate copies. Finish on the table view with the prepared portfolio visible and ready for the buildings, units, and lease workflows that follow.
