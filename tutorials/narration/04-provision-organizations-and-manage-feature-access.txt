This tutorial shows how a Super Admin reviews a prepared synthetic organization and controls its optional feature access. In a real onboarding, search before provisioning so you never create a duplicate. Use approved legal, address, contact, and tax data only; these values can appear on documents and communications. This recording uses the prepared RentAxis Tutorial Studio tenant, so it does not create another production organization.

Open Organizations and review the tenant list. Confirm that RentAxis Tutorial Studio is active, then search for its exact name. Check the identifier and address before opening any settings. A tenant name and status are not enough by themselves: always verify the record you intend to change.

Open Feature Toggles for the selected organization. RentAxis keeps optional capabilities disabled until they are deliberately assigned. Listings enables publication and marketplace discovery. Meetings enables scheduling between property teams and renters. Email Notifications enables supported outbound delivery. Lease Renewals enables renewal opportunities, reminders, and renter intent. Gate Pass enables resident visitor credentials and security operations. The prepared tenant has these five capabilities enabled for the tutorial workflow. In a real customer account, change only the features allowed by the contracted plan and operational readiness.

After saving a feature change, wait for the confirmation and refresh the dialog. Each selected toggle should remain enabled after reload. If a menu is still absent, check both the feature toggle and the signed-in user’s role; never borrow a broader account just to expose a screen.

Use the organization switcher to enter the tenant context and verify the organization name in the header before creating, editing, or deleting any record. Feature access is tenant-scoped, while role access determines which people can use it. To finish, return to the organization record and note where legal details can be corrected and where an organization can be deactivated. Do not deactivate a tenant while dependent recording fixtures or customer data still exist. Careful identity checks, deliberate feature access, and least-privilege roles keep onboarding safe and repeatable.
