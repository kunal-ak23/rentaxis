Your own systems can read the units you promote to, through the promoter API. In the promoter portal, open the Developer tab. Select Create key, name it Production sync, and select Create. The full key is shown now, and only now: Miftah keeps a fingerprint of it and can never show it again. Select Copy, put it in your secret manager, then select I've saved it. The key is listed as Active, by its first characters only. On your server, every call sends the key in the X-Api-Key header. Ping checks that the key works, and answers with the promoter and the organisation it acts for. Units count is the cheap call: two properties, eight units, and a fingerprint of the whole list. Units returns the list itself, a page at a time: each unit's ID and number, and its property's ID and name. Nothing about tenants, contracts or payments is ever included. Every page carries the same fingerprint. That fingerprint keeps your copy in sync cheaply. Every fifteen minutes, call units count. If the fingerprint is the one you stored, nothing has changed. If it differs, fetch every page of units and replace your list in one step. Now let the coupon carry the unit. Open Ads and edit the coupon. Its link already passes the code. Select Add parameter: unitId, from Unit ID. Add another: propertyId, from Property ID. Tenants are asked before their details are shared, and the example shows the finished link. Save, and the ad goes back to an administrator for approval. On the tenant's phone, they tap Copy and the code is copied. Because the link carries their unit, they are asked to agree first. Then the phone itself opens the https link: in your app, if it has verified Universal Links or App Links for your domain, otherwise on your website. Custom app schemes are refused. Once the ad is approved again, a tenant in A-102 opens this link. Take the unitId and look it up in your synced units: it is A-102 in Oasis Crest Residence Tower, one of your units. An ID that is not in your list is not one of yours. Whether a code was already used is your own rule: Miftah does not track redemptions. To replace a key without downtime, select Rotate. The new key is shown once, like the first. The old key is now Expiring: it keeps working for twenty-four hours while you move your servers over. When everything uses the new key, revoke the old one. The reason is optional, and the key stops working at once. If a key leaks, Miftah can stop it too. A super admin opens API keys and pastes the leaked key into the search, which finds that one key in any organisation. Select Revoke, give the reason, which is required here, and confirm. Back in the Developer tab, the key shows Revoked by Miftah admin, with that reason. Create a new key whenever you need one.
